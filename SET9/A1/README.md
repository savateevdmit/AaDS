## Тестируемые алгоритмы:
1. Quick Sort (стандартный)
2. Merge Sort (стандартный)
3. String Merge Sort (с использованием LCP)
4. String Quick Sort (тернарный)
5. MSD Radix Sort (без переключения)
6. MSD Radix Sort + String Quick Sort (с переключением при размере подмассива < 74)

Алгоритмы реализованы на языке C++

## StringGenerator

Класс `StringGenerator` реализован на C++ и генерирует массивы строк для тестирования. Используется алфавит из 74 символов: заглавные и строчные латинские буквы `A..Z`, `a..z`, цифры `0123456789`, специальные символы `!@#%:;^&*()-`. Длина каждой строки - от 10 до 200 символов. Для каждого типа генерируется массив максимального размера (3000 строк), из которого берётся подмассив нужного размера.

| Метод | Описание | Возвращает |
|-------|----------|------------|
| `generateRandomString(len)` | Генерирует случайную строку заданной длины | `std::string` |
| `generateRandomArray(size)` | Случайный массив строк | `vector<string>` |
| `generateReverseSortedArray(size)` | Массив, отсортированный в обратном порядке | `vector<string>` |
| `generateNearlySortedArray(size)` | Почти отсортированный (5% перестановок) | `vector<string>` |
| `generatePrefixArray(size, prefix)` | Массив строк с общим префиксом `"hello_hse"` | `vector<string>` |
| `writeAllArraysToJson(fileName)` | Записывает все 4 массива в JSON-файл | - |

## StringSortTester

Класс `StringSortTester` выполняет сбор метрик производительности всех 6 алгоритмов. Каждый алгоритм запускается 5 раз для каждой комбинации типа массива и размера (от 100 до 3000 с шагом 100), результаты усредняются. Время измеряется с помощью `std::chrono::high_resolution_clock` в микросекундах. Результаты сохраняются в `data/measurements.json`.

| Метод | Описание |
|-------|----------|
| `runTests(inFile, outFile)` | Считывает массивы из JSON, запускает все алгоритмы на всех типах данных и записывает результаты |

Структура одного замера в JSON:
```json
{
  "array_type": "random",
  "size": 500,
  "algorithm": "STRING MERGESORT",
  "avg_time_us": 312,
  "avg_char_comparisons": 48721
}
```

## Адаптированные алгоритмы

### String Quick Sort (тернарный)

Тернарный String Quick Sort разбивает массив на три части: элементы с символом на позиции `d`, меньшим, равным и большим опорного. Для выбора опорного элемента используется первый элемент подмассива. Ключевая функция `charAt(s, d, comps)` инкрементирует счётчик при каждом обращении к символу строки.

```cpp
void stringQuickSort(vector<string>& arr, int low, int high, int d, long long& comps);
```

Теоретическая сложность: **O(W * n * log n)** посимвольных сравнений, где W - средняя длина строки.

### String Merge Sort (с LCP)

Использует структуру `StringLCP`, хранящую строку и длину её общего префикса с соседним элементом в отсортированном подмассиве. При слиянии функция `lcpCompare` начинает сравнение строк с позиции `min(lcp_P[i], lcp_Q[j])`, пропуская уже просмотренные совпадающие символы. После каждого сравнения значение LCP обновляется для следующего шага слияния.

```cpp
void stringMergeSort(vector<string>& arr, long long& comps);
```

Теоретическая сложность: **O(n * log²n)** посимвольных сравнений в среднем.

### MSD Radix Sort (без переключения)

Сортировка начинается с первого символа. На каждом уровне рекурсии выполняется counting sort по значению символа на позиции `d`, затем рекурсивно сортируются подмассивы строк с одинаковым символом на этой позиции. Посимвольные сравнения не выполняются - алгоритм только читает символы для подсчёта частот.

```cpp
void msdRadixSort(vector<string>& arr, long long& comps);
```

Теоретическая сложность: **O(n * W)** обращений к символам, где W - максимальная длина строки.

### MSD Radix Sort + String Quick Sort

Идентичен предыдущему алгоритму, но при размере подмассива менее 74 (мощность алфавита) рекурсия переключается на тернарный String Quick Sort. Это устраняет накладные расходы counting sort на массивах, меньших числа возможных символов: выделять 256-элементный счётчик для 5-10 строк нецелесообразно.

```cpp
void msdRadixSortWithCutoff(vector<string>& arr, long long& comps);
```

## Результаты

### Анализ числа посимвольных сравнений

#### Случайный массив

![comparisons_random](https://github.com/savateevdmit/AaDS/blob/main/SET9/A1/graphics/comparisons_random.png)

На случайных данных MSD Radix Sort (без переключения) делает меньше всего посимвольных сравнений, при n=3000 около 14 000 против 35 000-52 000 у остальных. Ternary Quick Sort делает меньше сравнений, чем Merge Sort и String Merge Sort: тройное разбиение эффективно распределяет строки по первому символу, и при случайных данных коллизий по первому символу мало. Стандартный Quick Sort и String Merge Sort дают почти одинаковое число сравнений, при этом MSD Radix Sort с переключением чуть уступает чистому MSD из-за дополнительных посимвольных сравнений в String Quick Sort на малых подмассивах.

#### Обратно отсортированный массив

![comparisons_reverse](https://github.com/savateevdmit/AaDS/blob/main/SET9/A1/graphics/comparisons_reverse.png)

На обратно отсортированных данных картина резко меняется. Стандартный Quick Sort деградирует до O(n²) посимвольных сравнений, при n=3000 около 4 560 000, что на два порядка больше всех остальных алгоритмов. Ternary Quick Sort также страдает от неудачных разбиений: 138 000 сравнений против 14 000-25 000 у MSD Radix Sort, String Merge Sort и Merge Sort. String Merge Sort работает лучше стандартного Merge Sort (18 000 против 25 000): на обратно отсортированных данных при слиянии правый подмассив почти всегда идёт первым, и LCP-значения переиспользуются эффективно.

#### Почти отсортированный массив

![comparisons_almost_sorted.png](https://github.com/savateevdmit/AaDS/blob/main/SET9/A1/graphics/comparisons_almost_sorted.png)

На почти отсортированных данных стандартный Quick Sort делает больше посимвольных сравнений, чем ожидается: при сравнении строк с длинными совпадающими началами каждый вызов сравнения начинается с первого символа заново. При n=3000 это даёт 229 000 сравнений против 28 000-45 000 у адаптированных алгоритмов. String Merge Sort лидирует среди алгоритмов, использующих попарные сравнения: использование LCP позволяет начинать следующее сравнение с позиции уже известного расхождения. MSD Radix Sort (без переключения) делает наименьшее число посимвольных обращений, при n=3000 около 14 000, что совпадает с результатами на случайном и обратном массивах: количество обращений к символам у него определяется суммарной длиной строк, а не порядком данных.

#### Массив с общим префиксом

![comparisons_common_prefix](https://github.com/savateevdmit/AaDS/blob/main/SET9/A1/graphics/comparisons_common_prefix.png)

На данных с общим префиксом `"hello_hse"` стандартные Quick Sort и Merge Sort делают существенно больше посимвольных сравнений, чем на случайных данных: каждое сравнение двух строк вынуждено проходить через 9 одинаковых символов до точки расхождения. Ternary Quick Sort и String Merge Sort справляются значительно лучше, около 26 000-34 000 сравнений против 122 000-175 000 у стандартных алгоритмов при n=1300. Ternary Quick Sort выигрывает за счёт того, что после разбиения по первому символу рекурсия уходит сразу на следующую позицию, минуя уже обработанный символ. String Merge Sort экономит на LCP: после первого сравнения двух строк длина общего префикса сохраняется, и следующее сравнение начинается сразу с позиции расхождения.

### Анализ времени выполнения

#### Случайный массив

![time_random](https://github.com/savateevdmit/AaDS/blob/main/SET9/A1/graphics/time_random.png)

На случайных данных MSD Radix Sort (без переключения) работает быстрее всех, при n=3000 около 1 300 мкс против 3 500-5 500 мкс у остальных. MSD Radix Sort с переключением медленнее чистого MSD примерно в два раза, несмотря на меньшее число посимвольных обращений: накладные расходы на проверку порогового условия и вызов рекурсивного String Quick Sort сказываются на времени. Стандартный Quick Sort оказывается быстрее, чем Merge Sort и адаптированные алгоритмы на основе слияния, 3 500 мкс против 4 500-5 500 мкс. String Merge Sort работает сопоставимо со стандартным Merge Sort.

#### Обратно отсортированный массив

![time_reverse](https://github.com/savateevdmit/AaDS/blob/main/SET9/A1/graphics/time_reverse.png)

На обратно отсортированных данных стандартный Quick Sort работает сильно дольше: при n=3000 время составляет 263 000 мкс, что в 50 раз медленнее MSD Radix Sort (1 300 мкс). Причина, выбор первого элемента в качестве опорного: на обратно отсортированном массиве каждое разбиение делит подмассив на части размером 0 и n-1, что даёт O(n²) сравнений строк. MSD Radix Sort и String Merge Sort лидируют по скорости, порядок данных не влияет на их работу. Ternary Quick Sort также страдает от неудачных разбиений: 17 000 мкс против 1 300-5 200 мкс у остальных адаптированных алгоритмов.

#### Почти отсортированный массив

![time_almost_sorted](https://github.com/savateevdmit/AaDS/blob/main/SET9/A1/graphics/time_almost_sorted.png)

На почти отсортированных данных стандартный Quick Sort снова показывает нестабильное время: при n=3000 около 14 700 мкс, тогда как MSD Radix Sort укладывается в 1 200 мкс, а String Merge Sort, в 4 100 мкс. Нестабильность Quick Sort объясняется тем, что почти отсортированный массив с первым элементом в качестве опорного приводит к разбиениям, близким к вырожденным. String Merge Sort работает быстрее стандартного Merge Sort (4 100 мкс против 5 200 мкс): переиспользование LCP сокращает число фактически выполняемых сравнений. Ternary Quick Sort остаётся медленнее остальных адаптированных алгоритмов, 5 600 мкс.

#### Массив с общим префиксом

![time_common_prefix](https://github.com/savateevdmit/AaDS/blob/main/SET9/A1/graphics/time_common_prefix.png)

На данных с общим префиксом разрыв по времени между адаптированными и стандартными алгоритмами увеличивается: MSD Radix Sort не сравнивает строки попарно, а String Merge Sort после первого сравнения помнит длину общего префикса и не просматривает его снова, тогда как Quick Sort и стандартный Merge Sort при каждом новом сравнении проходят префикс с первого символа. При n=1300 стандартные алгоритмы тратят 3 000-3 200 мкс против 1 200-1 800 мкс у Ternary Quick Sort и MSD Radix Sort. String Merge Sort и Ternary Quick Sort работают почти одинаково быстро, несмотря на то что у Ternary Quick Sort меньше посимвольных сравнений: накладные расходы на рекурсию и перестановки элементов выравнивают результат.

## Сравнение с теоретическими оценками

| Алгоритм | Теоретическая сложность | Наблюдение |
|----------|------------------------|------------|
| Quick Sort (стандартный) | O(n * W * log n) | Деградирует до O(n² * W) на обратных и почти отсортированных данных из-за выбора первого элемента опорным |
| Merge Sort (стандартный) | O(n * W * log n) | Стабилен, слабо зависит от типа данных |
| String Merge Sort | O(n * log²n) | Выигрыш за счёт LCP особенно виден на префиксных и почти отсортированных данных |
| Ternary Quick Sort | O(n * log n + W * n) | На обратных данных много лишних разбиений; на префиксных выигрывает у стандартных алгоритмов |
| MSD Radix Sort | O(n * W) | Число посимвольных обращений не зависит от порядка данных; стабильно лучшее время |
| MSD Radix Sort + Quick | O(n * W) с меньшей константой | На практике медленнее чистого MSD из-за накладных расходов на переключение |

## Выводы

### По числу посимвольных сравнений

- MSD Radix Sort не выполняет попарных посимвольных сравнений - он только читает символы для подсчёта частот, поэтому счётчик посимвольных сравнений у него минимальный среди всех алгоритмов.
- String Merge Sort эффективно использует информацию о LCP: на данных с общим префиксом каждое повторное сравнение начинается с позиции уже известного расхождения, что существенно сокращает число посимвольных сравнений.
- Ternary Quick Sort требует больше посимвольных сравнений, чем стандартный Quick Sort, на обратно отсортированных и случайных данных - тройное разбиение и неоптимальный опорный элемент приводят к лишним уровням рекурсии.
- Стандартный Quick Sort делает больше посимвольных сравнений, чем ожидается, на почти отсортированных и префиксных данных: каждое сравнение двух строк начинается с нулевой позиции и проходит весь общий префикс заново.

### По времени выполнения

- На случайных и почти отсортированных данных быстрее всего работает MSD Radix Sort (без переключения).
- На обратно отсортированных данных стандартный Quick Sort деградирует до O(n²), при n=3000 время составляет 263 000 мкс против 1 300 мкс у MSD Radix Sort.
- Ternary Quick Sort и MSD Radix Sort с переключением стабильно медленнее остальных из-за глубокой рекурсии и накладных расходов.
- На данных с общим префиксом разрыв по времени между алгоритмами увеличивается: MSD Radix Sort не сравнивает строки попарно, а String Merge Sort после первого сравнения помнит длину общего префикса и не просматривает его снова, тогда как Quick Sort и Ternary Quick Sort при каждом новом сравнении проходят префикс с первого символа.

Наиболее универсальным алгоритмом по совокупности обеих метрик оказался MSD Radix Sort - он не выполняет попарных посимвольных сравнений и показывает конкурентное время выполнения на всех типах данных.
